# PC feature audit 2026-11-14

Tested the published Baritone Bedrock **1.7.0** DLL and control panel with
Minecraft Bedrock **26.63** (Windows package `1.26.6301.0`). Source release
commit `422d92d8ba489c44c64e0d26acad9cb685765f15`. Live tests used existing
local worlds. Temporary blocks, objects and test tasks were removed, and the
original inventory was verified slot by slot. Normal Minecraft commands supplied
temporary fixtures and restored consumed test resources.

139 C++ tests and 5 Python recipe importer tests passed. The C++ suite also
passed under AddressSanitizer. All 105 primary commands returned their help and
usage in the running release. The retained logs record direct invocation of at
least 78 primary commands, including aliases resolved to their primary names.
An invocation can be a status query, a guard check, or part of a full scenario.
The matrix records the observed outcomes.

## Fix order

1. **World identity and persistent state.** Put a seven-second wait task in
   the queue of one existing world and leave it paused. Exit, then open a
   different save with the same display name and dimension. `#task list`
   displayed the waiting task in the second save. No task was run there. The
   two saves displayed different player positions and used the same checkpoint
   path. `Bot::identity()` uses the display name and dimension, and
   `Bot::worldDataPath()` hashes the display name. The same key is used for
   workflows, construction checkpoints, protection, storage and placements.
   Waypoints and the chunk cache also derive storage names from the display
   name. Fix this first because a user can resume an action against the wrong
   world. Bind saved state and map requests to a stable, unambiguous world ID.
   Preserve legacy data and require an unambiguous mapping before migrating it.
   Regression criterion: two saves with the same name and dimension retain
   separate tasks, protections, map destinations and construction checkpoints
   after leaving, reentering and restarting the game.
2. **Replacement without the replacement item.** Place one temporary
   cobblestone block. With no grass block in inventory, select that position
   and run `#sel replace cobblestone grass_block`. The builder removed the
   cobblestone, then reported missing materials and paused. A native block-state
   read showed air. `BuilderProcess::tick()` considers breaking a nearby wrong
   block before its material and placement checks. Require a usable replacement
   item before removing the source block in replacement jobs. Regression
   criterion: the source block survives a missing material, and replacement
   succeeds when the material becomes available. Keep deliberate clearing and
   mining operations working.
3. **Navigation announces arrival before the player settles.** In the local
   Creative test world, `#goto 1167 68 -8` reached the destination on all three
   instrumented runs. The descent to `1165 67 -8` announced `Arrived!` every
   time and settled at `1164 67 -8` in two of three runs. One map navigation
   request also settled one block past its target on the Z axis. The trace
   shows horizontal velocity during the final descent. Check terminal movement
   braking and the timing of `CustomGoalProcess` completion. Regression
   criterion: position still satisfies the goal after motion settles, before
   workflow completion or automatic disconnect.

### Secondary findings

- `#storage scan all` tries registered furnaces, then marks the survey
  incomplete because those stations expose furnace slots. This was reproduced
  after successful cooking. Skip workstation types that the storage survey
  cannot index, or identify them explicitly when registering locations.
- `#workflow template equip <profile>` loaded and stayed paused as expected.
  Running it with the required items already in the correct hotbar slots
  stopped with `Register a supply container with #storage add first`. Direct
  `#loadout equip` completed. The template routes through logistics, which
  requires a registered source before checking whether any items are missing.
- An immediate `#history list` after `Build complete` omitted a new placement.
  The entry appeared in a later check, and conditional undo worked. The
  history observer confirms changes after a delay. The checks treat immediate
  visibility and eventual undo as distinct behavior.
- `#farm 2` harvested a mature wheat plant in Creative and replanted it. A
  native block-state check showed growth 7 before and growth 0 afterward. The
  process reported `Farming failed` as soon as it had no remaining work. Give
  normal exhaustion of eligible crops a distinct status from pathing failure.
  Both test blocks were restored to air and the inventory matched the baseline.

## Windows regression checks after the fixes

- Two existing local saves named “Mon monde” in dimension 0 exposed distinct
  save keys and checkpoint paths. In the second save, the queue was empty,
  the first save's test zone was absent, and its map destination was rejected.
  On reentry, the first save recovered its paused queue and protected zone.
- The six repeated navigation runs ended on the requested block after settling,
  including all three descents. Automatic disconnect from a stationary goal
  returned to the world selection menu.
- `#sel replace` kept the original cobblestone when the target material was
  missing. A replacement with available stone succeeded, and explicit
  `#sel cleararea` removed the temporary block.
- `#farm` harvested and replanted the mature wheat in Creative and reported
  completion. The equip workflow finished with an already supplied loadout
  and zero registered containers. A mixed chest and furnace survey indexed
  the chest and completed.
- All 142 C++ tests and 5 Python importer tests passed. After the live checks,
  the inventory, position, fixture blocks, task queue and protection were
  checked against their initial state. Raw evidence is under
  `re/audit-fixes-*`.
